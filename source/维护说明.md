# 修复源码与重建

`launcher_repair.py` 是下载、环境诊断和界面接入的修复层；`launcher_local.py` 负责网盘入口、本地解压、模型归位、Python 恢复及进度窗口；`launcher_dependencies.py` 负责固定版本的国内源下载、独立目录安装和失败撤回；`launcher_updates.py` 负责版本比较、更新包验证、替换、备份和重启确认；`launcher_build.py` 是唯一可编辑的版本来源。原启动器的完整源文件已丢失，原界面和其余逻辑继续使用 EXE 内的原始编译模块。`original-launcher-main.marshal` 是读取出的原主模块备份，只能在兼容的 Python 版本中反汇编或分析，不能当作完整 Python 源码。

重建时使用 **Python 3.10**，只需标准库：

```powershell
python rebuild.py "C:\路径\Krita一键启动器.exe" "C:\路径\Krita一键启动器-修复预览.exe"
```

输入必须是原始启动器，不要用已经打补丁的副本作为输入。原 EXE 的 SHA256 为：

```text
8eec43719347e82f4480c9786827e1988b05f457621c8f42c3c4b80d9b4b653a
```

`rebuild.py` 将原 PYZ 里的 `launcher_main` 保留为 `launcher_legacy`，新增入口及修复模块；不运行原程序。无界面的版本查询和更新入口在导入原界面前处理。重建后会逐项验证原来 602 个打包模块和 1014 个未修改的外层条目没有变化，并校验完成 EXE 中的实际构建版本。

修改版本时只改 `launcher_build.py`。构建会生成 `version.preview.json`（预览渠道）或 `version.json`（正式渠道），其中大小、哈希和版本来自该次生成的 EXE。请将该 EXE 作为 `KritaLauncherSetup.exe` 上传到清单对应的固定 Release 标签下。更改文件名不改变哈希；上传其他构建的 EXE 会被修复版拒绝。

原界面导入时捕获的函数默认值不能通过修改模块变量自动更新，所以更新比较函数在每次调用时读取 `module.APP_VERSION`。不要改回 `local_version=APP_VERSION` 的默认参数形式。

测试命令（仍用 Python 3.10，在 source 目录执行）：

```powershell
python -X utf8 -B -m unittest discover -s tests -v
```

更新测试默认读取上一级的 `Krita一键启动器-修复预览.exe`；可用环境变量 `KRITA_UPDATE_TEST_EXE` 指定其他构建。测试只在自己创建的临时目录写入占位文件，不运行旧程序。

更新任务记录在 `%LOCALAPPDATA%\DrowmAI\launcher_updates\任务编号`。`plan.json` 记录目标路径和文件身份，`state.json` 记录状态，`update.log` 记录过程。旧 EXE 备份保留在原目录，名称带 `.update-任务编号.bak`。收到 `confirmed` 之前不能显示更新成功。

当前共有 57 项测试。实际国内源下载、限速进度界面和隔离目录更新记录在上级目录，未把测试下载文件混入交付包。

`course-packages.json` 是从已检查的魔搭核心包元数据中提取的 144 个依赖版本，构建时嵌入 EXE；仅用来约束检测到的缺失普通依赖。现存包损坏优先使用已安装版本；没有基准版本的未知依赖不会猜测最新版。CUDA/Torch 专用包不走普通 PyPI 自动修复。更换课程核心包时，先完成实际工作流验收，再重新提取、核对这份清单。

`course-core.json` 保留此前魔搭核心包检查的大小、SHA256 和版本快照。旧离线导入按钮已由“手动下载”取代；新入口不拿这份魔搭哈希冒充网盘压缩包的哈希，而是检查 ZIP 路径、完整性及便携包结构，复制模型后做哈希核验。若要恢复现有 Python，还会核对当前 ComfyUI 主文件和 requirements 与 ZIP 一致。未来取得网盘完整 ZIP 并确认来源后，可以再登记对应发布包的 SHA256。

普通依赖下载使用 --no-deps 和固定版本，完成后离线安装到 python_embeded/_launcher_packages/repair_*；用 site-packages 下的 zz_drowm_repair.pth 启用。复查失败会恢复原 .pth。不要直接改成无版本的 pip install -U -r requirements，也不要添加先卸载 Torch 的流程。

`repository-files-20261116.json`、上级目录的核心包检查记录保留本次远程检查依据。它们是检查快照，不代表仓库以后不会更新。在线安装每次会重新取仓库的长度和哈希，现有断点仅在文件身份一致时复用。

后续若恢复完整 UI 源码，可将下载器和诊断函数直接迁回源码，结束对原编译模块的依赖。正式对学员发布前应补做故障电脑下载、驱动兼容和课程完整工作流测试。
